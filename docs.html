Saisir une recherche

Les champs de départ et d'arrivée acceptent trois niveaux de précision.

Un pays
France interroge les 22 aéroports français, Grèce les 10 aéroports grecs.
Une ville
Paris interroge CDG et ORY, Londres ses cinq aéroports.
Un aéroport
CDG ou Charles de Gaulle n'interroge que celui-là.

Sous chaque champ, une ligne indique quels aéroports vont être interrogés. C'est le moyen de vérifier que la saisie a été comprise avant de lancer la recherche.

Graphies acceptées

Les accents et la casse sont ignorés : grece, Grèce et GRÈCE donnent le même résultat. Les noms anglais fonctionnent (Spain, Greece), ainsi que les graphies locales et les anciens noms de villes : Köln, Wien, Milano, Bombay, Saigon, Peking, Majorque, Tahiti, Corse.

Un piège sur les codes de trois lettres

Certains codes IATA sont aussi des mots français : VIE, LIS, SIN, DEL, MAD, MEL. Ces codes ne sont reconnus qu'en majuscules, pour éviter qu'une saisie comme « vie » soit interprétée comme Vienne.

La base est embarquée dans la page. Aucune requête réseau n'est nécessaire pour chercher un vol, ce qui explique que l'application fonctionne hors ligne une fois chargée.

Les horaires sont plausibles, pas réels. Les routes, les fréquences et les numéros de vol sont générés à partir de la géographie, de l'importance des aéroports et des compagnies nationales de chaque pays. Ils respectent des contraintes physiques vérifiées, mais ne correspondent pas aux programmes publiés par les compagnies. Pour des données réelles, voir le mode temps réel.

Comment les horaires sont calculés

Un vol est stocké comme ceci :

AF6019 → ['CDG', 'NRT', 1411, 807, 'B777-300ER', '2E', '1']
//        dép    arr   23:31  13h27  appareil    terminaux

Aucune heure d'arrivée n'est enregistrée. Chaque vol porte seulement son heure de départ locale et sa durée bloc. L'arrivée, le décalage de jour, le libellé de fuseau et la distance sont recalculés à chaque affichage, à partir des fuseaux horaires IANA.

Cette contrainte a une conséquence utile : une durée ne peut pas contredire les horaires affichés, puisque les horaires en découlent. Le changement d'heure est géré sans intervention. Le même vol Paris-New York affiche UTC+1 → EDT le 28 mars et UTC+2 → EDT le 29.

Les durées sont dérivées de la distance orthodromique entre les deux aéroports, puis validées contre une enveloppe de vitesse réaliste. Les 14 222 vols passent ce contrôle.

Un vol parti après minuit et arrivant le même jour ne porte pas de mention de décalage. À l'inverse, un Sydney-Los Angeles arrive à une heure locale antérieure à son départ, et s'affiche sans décalage de jour : c'est correct, le vol traverse la ligne de changement de date.

Mode temps réel

Par défaut, SkySearch n'interroge aucun service externe. Le bouton Source des données en pied de page permet de renseigner une clé chez un fournisseur, ce qui donne accès aux vols réels du jour avec statut, retard, porte d'embarquement et tapis bagages.

AeroDataBox
statut, retards, portes, terminaux, tapis. Clé via RapidAPI, offre gratuite limitée puis à partir de 5 $ par mois.
Aviationstack
statut, retards, terminaux. L'offre gratuite ne sert qu'en HTTP, ce qu'un navigateur refuse depuis une page HTTPS : le proxy est alors obligatoire.

La règle des deux aéroports

Une recherche France → Grèce couvre 22 × 10 aéroports. Interroger le fournisseur demanderait 22 appels pour une seule recherche, ce qui épuiserait n'importe quel quota en quelques minutes.

SkySearch ne le fait pas : au-delà de deux aéroports d'un côté ou de l'autre, la base embarquée répond seule, et les résultats le signalent. Pour obtenir les vols réels, il faut préciser une ville ou un aéroport.

Où va votre clé

SkySearch est une page statique : elle ne peut rien dissimuler. La clé est conservée dans le stockage local de votre navigateur et transmise uniquement au fournisseur choisi. Elle n'apparaît jamais dans le code du dépôt.

Attention si vous publiez votre propre version. Une clé saisie dans un navigateur est lisible par toute personne qui ouvre les outils de développement. Tant que chaque utilisateur saisit sa propre clé, le modèle tient. Si vous diffusez l'application avec votre clé, déployez le proxy.

Comportement en cas d'échec

Clé refusée, quota, délai dépassé
bascule sur la base embarquée, avec un message
Appel bloqué par le navigateur
même bascule, avec une suggestion d'activer le proxy
Réponse vide
la base est consultée avant d'annoncer un échec
Hors ligne

Les réponses du fournisseur sont conservées quatre-vingt-dix secondes, en mémoire et sur disque, pour éviter de consommer le quota sur des recherches répétées.

Le proxy

Le fichier worker.js du dépôt est un Worker Cloudflare prêt à déployer. Il règle trois problèmes à la fois : la clé reste côté serveur, les en-têtes CORS manquants sont ajoutés, et les fournisseurs qui n'exposent que HTTP sont réécrits en HTTPS.

npm i -g wrangler
wrangler init skysearch-proxy
# remplacer src/index.js par worker.js
wrangler secret put AERODATABOX_KEY
wrangler deploy

Collez ensuite l'URL du Worker dans le champ Proxy des réglages et laissez le champ de clé vide. Le Worker maintient une liste blanche d'hôtes autorisés : sans elle, il deviendrait un relais ouvert utilisable par n'importe qui.

Liens de partage

Une recherche se partage par son adresse. Les paramètres acceptent un code pays, un code IATA ou un nom.

index.html?from=FR&to=GR&date=2026-10-05
index.html?from=CDG&to=JFK
aeroports.html?q=Grèce

Hors ligne et installation

Un service worker met en cache la page, la base et les scripts au premier chargement. Les recherches suivantes fonctionnent sans connexion, en mode base embarquée.

Sur iPhone, l'installation passe par Partager puis Sur l'écran d'accueil. Sur Android et sur ordinateur, le navigateur propose l'installation directement.

Le mode hors ligne exige un service worker, donc une page servie en HTTP ou HTTPS. Ouvrir le fichier directement depuis le disque ne suffit pas.

Limites

  • Horaires générés. Plausibles et géographiquement cohérents, mais pas conformes aux programmes réels des compagnies.
  • Numéros de vol générés. Le lien « statut en direct » peut ne rien trouver pour un vol issu de la base. En mode temps réel, les numéros viennent du fournisseur et les liens fonctionnent.
  • Vols sans escale uniquement. Aucun calcul de correspondance. Une liaison absente des résultats existe souvent avec une escale.
  • Aucun prix. Voir la page Objectif pour les raisons.
  • Pas de sièges, pas de réservation. SkySearch informe, il ne vend rien.

Modifier la base

La base est générée, pas écrite à la main. Le dossier tools/ du dépôt contient trois scripts Python.

airports.py
le registre des aéroports, des pays et des alias de villes
genflights.py
construit le réseau de routes, les fréquences, les durées, et valide le tout
encode.py
produit data.js
cd tools
python3 genflights.py
python3 encode.py

Ajouter un aéroport demande son code IATA, sa ville, le nom de l'aéroport, son pays, ses coordonnées, son fuseau IANA et un rang de hub de 1 à 3. Le générateur s'occupe du reste : routes, durées, compagnies, numéros de vol.

Ne modifiez pas data.js directement, il est écrasé à chaque génération.
